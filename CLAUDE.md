# CLAUDE.md

Guidance for Claude Code working on **Skills Buddy**, a native macOS SwiftUI app that finds every agent skill installed on the Mac, shows where each came from, and keeps it up to date. The UI is built on [BlissUI](https://github.com/portseif/bliss-ui); its own CLAUDE.md has the component, token and accessibility rules, so follow it for UI work.

## Quick reference

- **Build:** `xcodebuild -project SkillsBuddy.xcodeproj -scheme SkillsBuddy -configuration Debug -derivedDataPath .build/DerivedData build`
- **Test:** the same command with `test`. Tests use Swift Testing (`import Testing`, `@testable import Skills_Buddy`).
- **XcodeGen:** the project is generated from `project.yml`. Run `xcodegen generate` after adding or removing a file and commit the regenerated `project.pbxproj`.
- **Swift settings** match BlissUI: Swift 5 mode, `MainActor` default isolation, approachable concurrency. Services are `nonisolated struct`s; off-main work is `@concurrent`, calls `warnIfOnMainThread`, and uses `runOffMain` / `concurrentMap` from `Services/OffMainThread.swift`.
- **BlissUI** comes from GitHub (`from: 2.0.0` in `project.yml`, the exact version pinned in `Package.resolved`). To work on both at once, add the local checkout with File › Add Package Dependencies › Add Local….

## Releasing

- Bump `MARKETING_VERSION` in `project.yml`, run `xcodegen generate`, commit and push, then `scripts/release.sh notes.md`. Tags have no `v` prefix (`0.1.1`). The script needs a Developer ID Application certificate and a `notarytool` keychain profile, and its git, network and keychain steps fail inside a sandboxed shell.
- `SkillsBuddy/Info.plist` says `CFBundleShortVersionString` 1.0, but the build setting wins: the built app reports `MARKETING_VERSION`.
- The app has no update check for itself. The README's Download link points at the latest GitHub release.

## How skills are found (`Services/SkillScanner.swift`)

- `skills list -g --json` (the Vercel `skills` CLI) reports each global skill once with the agents that load it. It only looks one level into each agent's skills folder, and it merges copies by their frontmatter `name`. `skills remove` likewise only touches those top-level folders.
- **Hermes** also loads skills from category folders at any depth (`~/.hermes/skills/creative/<name>`). `hermesSkillFolders(in:)` walks that folder with Hermes's own rules from `agent/skill_utils.py`: follow symlinks, skip its `EXCLUDED_SKILL_DIRS` (`.hub`, `.archive`, `.git`, `node_modules` and the rest) and a skill's `SKILL_SUPPORT_DIRS` (`references`, `templates`, `assets`, `scripts`), and keep walking inside skills. Other hidden folders are walked, because Hermes walks them.
- A nested Hermes skill's `folderName` is its path inside the Hermes folder (`creative/humanizer`). That keeps `Skill.id` (`skill:<folderName>`) unique when two categories hold the same name, and lets `AgentDefinition.skillFolderURL(named:)` resolve the nested folder. `DisabledSkillStore` stores each item under `originalURL.lastPathComponent` for the same reason.
- Actions work on each agent's install (`SkillAgentInstall.folderURL`). Disable moves it into the store and Enable puts it back at the recorded path; Remove runs `skills remove` for CLI skills and moves everything else to the Trash.
- `FileManager.contentsOfDirectory(at:)` doesn't list through a symlinked folder. List the resolved path by name and join each child to the path as found.
- `Resources/Agents.json` is generated by `scripts/generate-agent-registry.py` from the CLI's `docs/agents.md`.

## Performance

- Each skill row is about 660 KB of SwiftUI view graph, so built rows are most of the app's memory: with all 84 of the author's skills built it sits near 169 MB, against 69 MB when only the visible rows are. The table is a `BlissTable` with `isLazy: true`, which only builds lazily with BlissUI's lazy-rows fix (2.4.0 wrapped the rows in one `VStack`, so the flag built them all). A lazy stack keeps rows once built.
- Memory: `footprint <pid>` for the total, `heap <pid>` for live objects, `footprint --sample 0.1 --sample-duration 14 <pid>` to catch a transient spike. A spike that shows up as "Owned physical footprint (unmapped) (graphics)" is GPU surfaces, not the heap: the Activity dock's chevron used to cost ~240 MB per toggle by swapping SF Symbols (fixed in BlissUI by rotating one glyph). The table's built rows are the `ColumnProbeKey` `ForEachChild` count divided by 7 (one probe per column).
- Hitches: generate a few hundred throwaway skills in a temporary folder under `~/.hermes/skills/` (the nested walk picks them up), build Release, and record `xcrun xctrace record --template 'Animation Hitches' --attach <pid>` while scrolling. Start after the launch update check finishes, since its status updates re-render the table, and delete the folder afterwards.
- Accessibility clients hit-test the whole SwiftUI tree, so scrolling driven through accessibility (UI automation tools) costs far more than a real scroll. Measure with real wheel input.

## Tests

- Resolve temp directories first (`FileManager.default.temporaryDirectory.resolvingSymlinksInPath()`): `/var` is a link to `/private/var`, and paths built either way won't compare.
- `SkillScanner` runs end to end in a test with a fake home and a `SkillsCLI` whose `PATH` is empty. The CLI fails, so the scan falls back to `~/.claude/skills` and still walks the Hermes folder (see `DisabledSkillStoreTests`).
